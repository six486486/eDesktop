# 小栖的任务记忆

面向桌面工具交互的轻量实现。语义选择仍由本地 LLM 完成，每个前台回合只发起一次结构化生成；运行层约束参数、核对来源和实时状态、提交操作，最后显示真实回执。

## 三类信息

| 类型 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前任务 | 未补齐的提醒事项/时间、各字段的用户消息 ID 与时间、最近操作指代 | 当前进程内，30分钟；重新聊清除；重启不恢复执行 |
| 活动习惯 | 活动与专注时长、特定活动下某钟点的上午/晚上含义；原文证据、版本、更新时间 | 本地工作区 `petMemory.habits`，最多24条；明确修改或忘记 |
| 操作记录 | 已提交工具的实际结果、事项 ID、时长/提醒时间、源消息、使用的记忆 | 本地工作区 `petMemory.operations`，最近30天内最多40条 |

天气城市/播报时间、全局番茄钟设置继续由原业务配置管理，不复制成活动习惯。原有聊天偏好保留独立的低优先级机制。

## 执行过程

1. 接受用户消息并保存来源时间。按活动文字、最近指代和新近程度选择紧凑记忆；保留最多12条习惯标签和6条相关操作。近期聊天按完整问答组控制字符预算。
2. LLM 在同一次请求内输出意图摘要、一个结构化工具提议和回复。可选时间、记忆 ID 和证据片段由运行层提供；材料/能力询问不会取得写工具。
3. `TaskMemory.resolve` 将当前输入、尚未完成任务或明确选中的有效记忆绑定到字段。原话的确定时长覆盖活动习惯，活动习惯覆盖默认值；没有可验证依据的模型自填时长不作为默认值。
4. 工具再次验证真实待办/番茄钟状态、参数范围和事务所有权。业务变更与操作记录在同一个工作区事务里持久化，失败不留“成功经验”。提醒结果持久化 `runId` 回执，避免重复提交。
5. 真实回执更新当前任务的指代。已取消、完成或删除的提醒无法直接用旧 ID 复用。相对时长复用从本轮重算；历史具体钟点需重新说明本次时间。

工具回合使用 Ollama 的 [`think: false`](https://docs.ollama.com/api/chat) 参数，给短结构化结果保留输出额度；意图仍由 LLM 判断并输出简短 `assessment`。翻译、改写等材料任务只传入材料处理指引，避免业务工具说明干扰译文。

长期习惯仅接受当前用户的明确持久化要求。模型提议的活动和数值必须能对应到用户原话的同一分句；运行层可从唯一匹配的分句恢复证据，不把其他活动的时长拼接过来。一次性指令不会改写习惯。修改同类同活动习惯保留 ID、递增版本。

时间仍由程序计算。“明天”的日期以提供这个字段的那条消息为锚；“推迟十分钟”基于旧提醒时刻，“改成十分钟后”基于本轮时间。多条提醒无法绑定唯一目标时，请用户说明事项。

## 用户控制与可观察性

小铃铛内的“记住的事”提供习惯、最近操作两个列表，支持展开原话与逐条删除；也可以调用 `memory.recall` / `memory.forget`。删除记忆不撤销业务动作。新的消息、重新聊或删除记忆会阻止被取消的模型请求继续写入当前任务。

`runs.jsonl` 记录工具决定、状态、选中的记忆 ID、上下文字符数和耗时；诊断日志不复制提醒原文。用户原话和操作证据保存在程序旁 `data/desktop-workspace.json`，跟随原有便携数据路径。

这不是向量数据库或自动习惯挖掘。第一版采用本地小规模结构化索引和模型语义选择；超出检索窗口、相互冲突或无法验证的内容需要用户补充。没有加入自动计划、跨应用行为观察或后台自主执行。

单元/集成测试覆盖字段来源、跨午夜、过期/重置、活动覆盖、回执复用、失败保存、作用域、嵌套协议。Electron 用隔离工作区验证展示、原话展开、逐条删除和重启；真实模型脚本使用本机 Ollama，将合成请求和结果保存在 `.artifacts/pet-task-memory-ollama/`。这些测试不修改正式版的待办或个人记忆。
