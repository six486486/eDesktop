# 桌宠 · 小栖

小栖是 eDesktop 里的陪伴助手，负责对话、天气、到点提醒和少量番茄钟操作。用户可以继续直接点待办和番茄钟，也可以用一句话完成操作。使用入口见[项目首页](../README.md#小栖可以帮什么忙)。

这个目录把角色界面、模型请求和工具执行放在一起。宿主通过一个小接口接入现有工作区，桌宠不用另外维护一套待办。

## 一句话怎样变成操作

以“二十分钟后提醒我取快递”为例：

1. `harness.cjs` 保存用户消息，为这一轮创建 `runId` 和取消信号，读取当前工作区及相关记忆。
2. Ollama 模型通过 JSON Schema 输出 `assessment`、`decision { action, params }` 和 `response { text, visual }`。语义判断与回复共用一次前台请求，当前实现使用结构化工具分派，不依赖模型原生 `tool_calls`。
3. 运行层检查本轮允许的工具、参数形状、原话中的时间依据和最新目标状态。模型提议的事项 ID 必须来自实际工作区；中文数字、日期、相对时间和时长范围由程序校验、计算。
4. `reminder-service.cjs` 通过工作区修改队列创建真实待办，写入“临时安排”和绝对提醒时间。保存成功后才发布状态与回执。
5. 到点由程序调度并显示气泡，不再请求 LLM。修改或取消提醒后，以最新待办状态为准。

普通聊天在确认 `none` 决策后流式显示正文；工具轮隐藏模型草稿，等操作结束后显示真实结果。用户可以直接在待办组件里修改时间，小栖下一次操作仍会重新检查。

## 运行层管什么

- **工具范围。** 根据用户请求与当前状态开放有限工具。引用、翻译材料和能力询问不会因为包含命令字样就得到写入权限；不支持的未来开钟请求不能提前启动计时。
- **状态与来源。** 当前原话、未补齐的任务字段、明确选择的记忆，各自保留依据。即使模型绕过 Schema 提议了操作，执行前仍检查权限、字段和真实状态。
- **取消与迟到结果。** 新消息、停止回复、重新聊或切换模型会取消旧请求。每次异步返回再核对 `runId`，旧回复不能改变新一轮的文字、动作或工作区。
- **提交边界。** 工具使用现有工作区队列，保存前检查运行归属。开始提交后，停止回复不会撤销已经接受的操作。重复的运行标识复用回执，避免重复创建。
- **可观察性。** 本地诊断记录工具名、状态、取消原因、使用的记忆 ID、上下文大小与耗时。诊断日志不复制聊天正文；聊天与记忆中的原话另存于本地数据文件。

这些约束解决执行可靠性。模型仍可能误解一句话，测试也会区分“没有误执行”与“回答正确”。

## 天气、待办与番茄钟

点击聊天标题栏的小铃铛进入“天气与提醒”。天气默认不启用，可手动搜索城市、选择每天或周一至周五、设置播报时间。也可以说“播报改成九点”“周末不用报天气”。手动设置不依赖 Ollama，查询使用 [Open-Meteo](https://open-meteo.com/)，结果保留日期、温度和来源。

“我的一天”只检查当天未完成事项，默认提前 5 分钟，可改为开始时或提前 10/15 分钟。临时提醒写入“临时安排”；普通临时事项只有开始/结束时间时，不会自动生成提醒。取消提醒保留待办本身。

番茄钟复用已有组件，没有时会创建一个。支持立即开始 1–240 个整数分钟的专注、停止和查询；已有活动计时不会被重复启动。单次时长不改写组件默认设置，手动暂停、继续、重置和切换模式仍可照常使用。专注与休息结束均由主进程保存状态后通知桌宠。

提醒显示不抢焦点的气泡，不自动展开聊天或勾选完成。调度按绝对时间与持久化发生记录运行，重启和睡眠恢复后重新检查；临时提醒或天气过期 1 小时、我的一天开始后超过 15 分钟会略过。应用退出或桌宠关闭期间不弹出。

发生记录先保存再投递，避免重启重播。如果程序恰好在保存后、展示前退出，那次气泡可能被略过。这是当前交付语义，不保证每条通知恰好显示一次。

## 语音与动作

```text
麦克风 → MediaRecorder → 16 kHz 单声道 PCM
      → utilityProcess / sherpa-onnx / SenseVoice
      → 识别文字 → PetHarness → 原有工具
```

Ctrl+Alt+V 开始或结束录音，识别后自动发送。桌面模式保持聊天框收起，气泡显示声波、录音秒数、识别状态与回复。Esc 或 × 取消，普通聊天草稿不会因语音发送被清空。

每次录音有独立 ID 和所属窗口，过期识别结果不能发送命令。主进程限制麦克风申请来源、录音时长、PCM 大小与识别超时；识别进程结束后释放模型内存。录音只存在内存，不保存或上传音频。Ollama 离线时仍可识别文字，界面会保留原文并说明未能发送。

首次从 ModelScope 下载固定版本的 [SenseVoice 模型](https://modelscope.cn/models/pengzhendong/sherpa-onnx-sense-voice-zh-en-ja-ko-yue)，逐个检查大小与 SHA-256，模型约 229 MB，保留原始 LICENSE。识别依赖的 Windows DLL 和 `.node` 随应用分发，并从 `app.asar` 解包。

麦克风能量驱动平滑声波和竖耳姿态；喵叫动作跟随音频播放事件，耳朵与头保持连续轮廓，张嘴保留 W 形猫嘴。普通对话也可提出开心、专注或休息动作，运行层检查白名单、冷却时间和运行归属，取消后的动作不会补播。

到点声音是一段约 0.7 秒的内置猫叫，可在小铃铛内开关或试听。语音输入期间静音，恢复后不补播旧提醒。[音效来源与 CC0 许可](sounds/LICENSE.txt)随源码保留。

## 记忆与上下文

记忆主要服务日常工具操作，具体设计见 [TASK_MEMORY.md](TASK_MEMORY.md)。

| 信息 | 用途 | 保留方式 |
| --- | --- | --- |
| 当前任务 | 补全提醒事项/时间，理解“改成半小时”“再推迟十分钟” | 进程内保留 30 分钟，重新聊或重启清除 |
| 活动习惯 | “以后写代码45分钟”；特定活动下钟点的上午/晚上含义 | 明确要求才写入，保留原话来源、版本和更新时间 |
| 最近操作 | 查询上次的实际时长，再明确复用 | 只记录成功提交的操作，最近 30 天内最多 40 条 |

当前明确时长优先于活动习惯，活动习惯优先于组件默认值。一次性的“这次20分钟”不会改长期习惯；已取消、完成或删除的提醒不能直接复用旧目标。操作记录与业务变更在同一次工作区事务中保存，失败不留下成功记录。

上下文按完整问答组限制字符预算，优先放入当前任务、真实状态和相关记录，不把所有历史重复塞给模型。小规模结构化索引按活动、最近指代与时间选择候选，再由模型结合本轮语义选择。这里没有向量数据库，也不会从重复操作中偷偷总结新习惯。

小铃铛 →“小栖记住的事”可查看活动习惯、最近操作和来源原话，支持逐条忘记。删除记忆不撤销实际操作。原有称呼、回复长度和追问偏好保留为独立的低优先级聊天记忆，临时要求只作用于当轮。

## 数据与生命周期

正式版使用程序旁的 `data`：

- `desktop-workspace.json`：真实组件、提醒配置、活动习惯与操作记录。
- `desktop-pet/state.json`：最近聊天、聊天偏好、所选模型、桌宠位置和声音设置。
- `desktop-pet/speech/sensevoice/`：离线语音模型。
- `desktop-pet/*-runs.jsonl`、`runs.jsonl`：本地运行诊断。

这些文件含有用户自己的聊天、待办或使用记录，不随仓库和便携 ZIP 分发。天气查询会向 Open-Meteo 发送城市名或城市经纬度；对话交给默认本机 Ollama 服务，使用本地模型时在本机推理。

控制中心、托盘与桌宠右键菜单共享同一个开关。关闭会取消请求、停止桌宠调度、销毁窗口、移除 IPC 和快捷键，并卸载预热的聊天模型。收起聊天只隐藏窗口，回复可继续；“重新聊”清除近期聊天与待补全任务，保留已保存习惯和真实业务状态。

## 开发与验证

```powershell
npm run dev:pet
node --test desktop-pet/tests/*.test.cjs
npm run build
npm run test:pet-memory-ui
npm run test:pet-reminder-ui
npm run test:pet-voice-ui
```

`dev:pet` 使用 `.artifacts/desktop-pet-preview/` 下的隔离工作区，展示相同的待办和番茄钟组件。Electron 测试也使用隔离数据；语音 UI 测试使用系统合成的固定句子，需要中文语音组件和已准备好的离线模型，模型目录为 `.artifacts/voice-model/sensevoice/`。

测试覆盖结构化流解析、工具权限、字段来源、时间边界、保存失败、取消后的迟到结果、重启恢复、记忆删除和真实 UI 操作。真实模型检查需先启动 Ollama 并安装聊天模型：

```powershell
npm run test:pet-memory-model
npm run test:pet-semantics-model
```

模型测试保留合成输入、实际回答和失败结果，输出在被 Git 忽略的 `.artifacts/`。它们用于复现具体语义问题，结果会随模型与运行参数变化，不作为通用准确率。
